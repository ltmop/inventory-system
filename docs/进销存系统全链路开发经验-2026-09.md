## 二、架构决策与「为什么」

### 2.1 命令层复用（最关键）
- 桌面/手机/云端三端**共用 electron/commands/** 同一套业务逻辑
- 收益：统计口径全站统一（今日流水/低库存/毛利），改一处三端生效
- 教训：任何兜底逻辑必须与主路径同口径（负库存成本曾把售价写进成本，账歪了）

### 2.2 批次级库存 + 金额按分存（整数）
- inventory_batches 每批独立批次号/成本/货位
- 金额一律用「分」整数，杜绝浮点误差
- 低库存口径：COALESCE(min_stock, 默认阈值5)

### 2.3 原子事务
- 盘点/多商品开单：任一行失败整单回滚，不留半截烂账
- SQLite WAL 模式：断电不丢数据

### 2.4 密码派生密钥（PBKDF2）
- 多设备：所有设备输同一密码 → deriveKey(密码, 服务器盐) → 同一密钥 → 数据互通
- 服务器只存盐（泄露无害），密钥永不上传
- 教训：密码=密钥种子，**改密码 = 旧加密数据作废**（重置前必须导出备份）

### 2.5 数据目录硬编码 + 原子写
- 数据在 %APPDATA%/fishing-inventory/（品牌改名/换 appId 不丢数据）
- cloud.json 原子写（tmp+rename）+ 凭证四件套校验（userId/keyK/uploadToken/viewToken 缺一视为未配对）

## 三、UI / 前端经验

### 3.1 布局与导航
- 5 大页签（首页/入库/销售/库存/我的）+ 设置，取代 18 项更多菜单
- 侧边栏常驻 + 顶栏分类标题（TITLE_MAP）
- 适老化：大按钮、大字模式、深色模式（打烊不刺眼）

### 3.2 组件组织（src/）
- components/ 通用组件（LoginGate/UpdateBanner/ErrorBoundary/SplashScreen）
- components/layout/ 布局（Sidebar/TopBar/Layout）
- components/settings/ 设置子卡（BackupCard/StaffCard/MobileServerCard 等，自包含不走父 props）
- pages/ 页面 + lib/（api/store/version/license）+ store/（zustand）

### 3.3 用户视角的坑（Playwright 走查发现）
- **窗口标题/品牌名残留**：改名要全链覆盖（index.html title + main.js BrowserWindow + 侧边栏/顶栏/小票/启动屏），代码 review 看不见，真实启动才现形
- **设置页臃肿**：10 区块平铺 → 按 4 组分类（外观操作/数据备份/连接共享/账户支持）+ 顶部分类导航条（点击平滑滚动）
- **更新入口要在用户所在的界面**：设置页「检查更新」显示新版本后必须给「下载」按钮，不能只依赖底部 UpdateBanner 事件条
- **登录门必须有逃生通道**：单机系统老板永不被锁——「老板模式直接进入」（一键关员工登录门）

### 3.4 自动更新链路（易断的三处）
1. preload 必须暴露 onUpdateAvailable/onUpdateProgress 事件订阅（缺了就静默不弹）
2. UpdateBanner 必须在 App 根组件挂载（定义了不渲染 = 白写）
3. 设置页手动检查要与事件路径双保险
- 启动 10 秒自动检测 → 底部弹条 → 下载 → 主进程弹「重启安装」

## 四、后端 / 数据层经验

### 4.1 主进程架构
- electron/main.js：IPC 通道注册（ipcMain.handle）
- preload.cjs：contextBridge 最小桥 + 通道白名单（防任意调用）
- server.js：局域网手机看店 HTTP 服务（token 鉴权 + 安全头 + 限流）

### 4.2 限流（审计任务7 教训）
- 读接口：有效 token 按 token 维度 600/min（多设备同出口不误伤），无 token 按 IP 120/min
- 写接口：token 60/min，无 token 30/min
- 429 响应带 Retry-After + 中文提示
- 教训：纯 IP 限流在 NAT 多设备场景 60% 误伤（"10 用户崩溃"元凶），必须 token+IP 组合

### 4.3 云同步防爆破（任务2）
- login/bind：IP 限速 10/min + 连续失败 5 次锁 15 分钟（内存态，重启清零）
- register：每 IP 每天 20 上限（防灌号）

### 4.4 多机同步冲突检测（任务9）
- 乐观锁：上传带 x-last-sync（上次快照时间戳），服务端比对快照 mtime，冲突返回 conflict 拒绝覆盖
- 客户端持久化 lastServerAt 作乐观锁

### 4.5 测试（592 断言的核心经验）
- 断言必须从种子数据推导（SEED_*），不写死数字——写死 = 种子一改就漂移
- 断言推导化：期望值从 SEED_PRODUCTS/BATCHES/TRANSACTIONS 运行时计算
- 独立库测业务（cdb/wdb/mdb），不污染主库
- 失败要能在第一处 exit 定位（ok() 函数失败即退出）

## 五、云服务器 / 部署经验

### 5.1 服务器布局（43.128.20.39 腾讯云）
| 服务 | 管理方式 | 端口 | 说明 |
|------|---------|------|------|
| Caddy | systemd | 80/443 | 反向代理 + HTTPS 自动证书 |
| cloud-server | pm2 (inventory-cloud) | 3100 | 云同步 + 更新源 |
| ai-server | systemd (ai-gateway) | 17533 | AI 网关 |
| 官网 | Caddy 静态 | 443 | /var/www/junchengzn |

### 5.2 HTTPS 全链路（任务1）
- sync.junchengzn.com 域名 → Caddy 自动证书（Let's Encrypt）
- http://43.128.20.39 → 308 重定向到 https（堵明文通道）
- 官网域名加 /updates/* 别名（防官网域名下更新 404）
- 教训：配置了≠生效，要端到端实测（真实注册账号走 https 验证）

### 5.3 发布链（A4，最重要）
- **一条命令**：node scripts/release.mjs（前置检查→打包→ASCII产物+latest.yml→部署→三样验证）
- 前置护栏：publish.url 必须 https / 版本必须递增 / appId 检查 / SSH 连通
- ASCII 文件名（inventory-system-setup-x.y.z.exe，避开中文 URL 编码）
- latest.yml 由脚本生成（path 与文件必然一致）
- 部署前备份服务器旧文件（可回滚）
- 只部署产物，不碰服务器源码（避免旧版覆盖新版——本项目的血泪教训）
- 三样验证：latest.yml 版本 / sha512 匹配 / 更新包 GET 200
- 官网版本号更新用 node 正则（不用 bash sed 反向引用，$1 会被 shell 展开改坏链接）

### 5.4 SSH 密钥
- 服务器授权密钥变更要留意（adjczn 曾被拒，改 skey-junchengzn.pem）
- 密钥放 ~/.ssh/，ADMIN_KEY 等敏感信息不放桌面明文（移 pm2 环境变量）

## 六、优化思路（已做 + 待做）

### 6.1 已做的优化
- 断言推导化（种子驱动，消除漂移）
- 发布链脚本化（事故归零）
- 设置页分类（找功能快）
- 更新入口置顶 + 主动提示（启动自动检测）
- 登录逃生通道（不锁死老板）
- AI 产品定位（品牌统一）

### 6.2 待优化（排期）
| 项 | 思路 | 优先级 |
|----|------|--------|
| 主进程单线程 SQL | 写命令进队列 + 前端 loading；重查询移 worker | 架构活，排期 |
| 前端 UI 自动化测试 | 目前仅后端 592 断言，UI 靠手动；引入 Playwright 走查进发布链 | 中 |
| 发布链加 Playwright 走查 | release.mjs 内嵌 UI 走查（窗口标题/品牌/核心页渲染） | 中 |
| 云备份失败提醒 | 界面/飞书提醒（与驾驶舱每日体检联动） | 低 |
| model 草稿回填 | 沉睡榜-model草稿待确认 CSV（177 行）老板勾选后回填 | 业务 |
| C 档录货 | 8/10 后的货录入，账先对上 | 业务最高 |

### 6.3 给后来者的核心建议
1. **命令层复用是底线**——三端口径统一，别为"快"绕过
2. **测试断言从数据推导**——写死数字是埋雷
3. **发布前跑 release.mjs**——手动发布两轮事故的教训
4. **改服务器代码前先 diff**——旧版覆盖新版是最大事故源
5. **用户视角走查常态化**——Playwright 启动应用，代码 review 看不见 UI 缺陷
6. **单机系统永不锁死用户**——登录/更新都要有逃生通道
7. **数据正确性 > 功能 > 界面**——账歪了其他都不算完成
