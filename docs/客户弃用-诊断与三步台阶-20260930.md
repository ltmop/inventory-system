# 客户「不想用」的真实原因 + 三步台阶方案

日期：2026-09-30
来源：客户反馈「大部分人都是微信/支付宝支付，去微信里看就知道今天微信赚了多少，虽然没有毛利率和利润，但胜在不用手动录入商品信息，收入直观，觉得麻烦」

状态：**只做诊断与方案，未改任何实现代码。**

---

## 一、先把客户的话翻译成大白话

客户不是在抱怨功能差，是在算一笔账，结论是「不划算」：

| | 微信 / 支付宝账单 | 我们的 App |
|---|---|---|
| 收完钱之后要做什么 | 什么都不用做 | 还得把卖了什么录进去 |
| 得到的数字 | 今天微信收了多少 | 营业额 + 毛利率 + 利润 |
| 他真正要的那个数 | 有 | 有（但成本更高） |
| 每天多花的工夫 | 0 | 几十单 × 十几秒 |

**结论一句话：我们多给的两个数字他不需要，他唯一要的那个数字微信已经白给他了。增量 ≈ 0，成本 > 0。**

在他眼里这不是「升级」，是「加活」。所以任何往右边那列「多加功能」的努力，方向都是错的。

---

## 二、诊断结论：最小记账单元设错了

### 已经做过的提速（这些不是瓶颈）

- 常卖商品置顶：`electron/server.js:1525` `report:posQuickPicks`，近 30 天销量 TOP，点一下直接进清单
- 真扫码：`mobile/pages/pos.js:132` 原生条码识别
- 搜一个字：单字联想，服务员不用打字
- 挂单：人多来不及录可先挂起，回头一键取回

这些都是有效的，**但客户嫌的不是「慢」，是「要做」。**

### 真正的门槛在这里

```js
// electron/commands/outbound.js:173
if (!Array.isArray(items) || items.length === 0)
  throw new Error('开单商品列表不能为空')
```

**系统里最小的记账单元是「商品」，不是「钱」。不录商品，一分钱都记不进来。**

而我们最有价值的部分 —— 赊账、库存、利润 —— 全部锁在这扇门后面。客户还没进门，就被「录商品」劝退了。

---

## 三、三步台阶方案

### 台阶①：先让他零门槛进门 —— 允许「只记钱，不记货」

把最小记账单元从「商品」改成「钱」。今天卖的是什么可以以后再说，先把每天的流水抓住。

界面：今日页右下角常驻悬浮键「记一笔」→ 弹出面板只有两个字段（金额 + 收款方式）→ 「记下来」完成。
成本打个字 + 点个方式，**和微信一样便宜**。

这一步买到的东西：
- 现金、朋友转账、没走 App 的钱第一次被算进「一整天」
- 用上一两周，他会自己撞上那个问题：**「光有钱，我不知道啥好卖」**
- 那一刻他自己去拉「管货」，我们不用推

### 台阶②：用微信给不了的东西留住他（这套代码早就写好了）

| 能力 | 现状 | 代码位置 |
|---|---|---|
| 熟客欠款余额（含预收负数） | 已有 | `electron/commands/customers.js` `listCustomers` → `outstanding` |
| 还款登记（现金/微信/支付宝/其他，超额自动标预收） | 已有 | `commandRegistry.json` `payment:record` |
| 单人客户对账单 | 已有 | `customerStatement` |
| 有账目的客户禁止删除（保账目完整） | 已有 | `commandRegistry.json:1093` |
| 近 N 天销量 / 毛利排行 | 已有 | `electron/ai.js:665` |
| AI 日报（营业额/毛利/件数 + 异常） | 已有 | `electron/ai.js:388` |

**这其中最锋利的一条是赊账**：熟客拿货没给钱 —— 这笔钱微信账单里**永远不会出现**。这是纯增量，不存在任何替代品。

### 台阶③：话要翻成人话再讲

| 别说 | 要说 |
|---|---|
| 毛利率 32% | 这包饵进 8 卖 12，一包到手 4 块 |
| 库存周转率低 | 这箱子摆了仨月没动，三百块钱压在架子上 |
| 进销存数字化管理 | 每天顺手记个数，月底不用翻账本 |

客户明确了：**他不要毛利率和利润。** 继续用「毛利」当卖点，等于对着一个不痛的地方使劲按。

## 四、先判断这个客户是不是买家（花 10 秒，比改两星期值钱）

| 客户的样子 | 判断 | 怎么打 |
|---|---|---|
| 熟客拿货常不给钱，靠脑子或本子记 | **真买家** | 只讲赊账：「到底谁欠你多少」—— 一句话就能约线下 |
| 品种上百上千，常断货或压一堆卖不动 | **真买家** | 讲「该进什么、哪些压着钱」，他已经在吃亏 |
| 每天几十单，晚上想不起今天到底收了多少 | **可培养** | 台阶① 速记先进门槛，用顺了他自己会问「还能干啥」 |
| 品种不多、扫码就走、不赊账、当天账记得住 | **现在不是买家** | 别硬推，微信账单对他真的够用。留联系方式等他长 |

> ⚠️ 顺序不能反。**先问清楚客户有没有赊账，再决定打单一钩子还是做速记入口** —— 否则可能改了半天，改的是一个本来就不会买单的人。

## 六、两条红线（动手前先看）

**① 别直接放开 `outbound.js:173` 的空校验。**
那句 `throw` 护着的是库存批次扣减和毛利口径，拆了会让报表算不出成本（成本价 0 会让毛利虚高等于营业额）。
正确做法：给速记**单独一条落库路径**，标记为「未挂商品」，**不混进 `transactions` 表**。

**② 别为了让他用，承诺「以后能接微信自动同步」。**
上一轮已确认：个人收款码不向任何第三方开放流水接口，这是平台规则，不是我们做不到。答应了后面收不回来。

见客户第一句别说功能，说这句。
