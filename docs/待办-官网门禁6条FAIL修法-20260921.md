## 3. 修法（择一；推荐 A）

### A. 让本地副本与线上对齐（推荐）

```powershell
cd D:\junchengzn.com
git status --short        # 先看清那 5 个未提交文件是谁改的、还要不要
git diff --stat           # 再看改了什么
# 若确认"本地改完已发布、只是没提交" → 提交即可
git add docs/index.html index.html products/cockpit.html products/inventory.html products/minidb.html
git commit -m "site: 与线上对齐（桌面 1.1.13 / 手机 1.3.0）"
```

改完回应用仓库再跑一次 `npm run check:web`：期望 **A 段全过 + B 段转绿 + C 段全过**。

⚠️ **先看清再提交**：如果那 5 个改动是**网站线正在做的活**，不要抢（这正是我这次没动手的原因）。

### B. 承认"B 段只是本地副本健康度"，把话说清楚

`verify-site-version.mjs` 自己的注释（第 38 行）就写着：SITE_DIR 是
**"测试的输入路径，不是正确性依赖"** —— 所以 B 段红**不等于线上有问题** ✗。
但输出里它和线上检查混在一起打（都叫 "B"），下次还会有人误判 ✗。
建议：把 B 段的 PASS/FAIL 文案加上「（本地站点副本）」前缀，或拆成 `B-local` / `B-live` 两组 ✓。

## 4. 顺手查到一个**门禁盖不到**的真过期（建议补断言）

**官网首页的手机版号是 `v1.2.1`，而实际是 `1.3.0`** ——

| 位置 | 写的 |
|---|---|
| `https://junchengzn.com`（首页头部/产品卡） | `桌面 v1.1.13 · 手机 v1.2.1` ❌ |
| `https://junchengzn.com/download/` | `桌面 v1.1.13 · 手机 v1.3.0` ✅ |
| 服务器上的 APK | `fishing-inventory-mobile-1.3.0.apk` ✅ |

根因：门禁的桌面正则 `DESKTOP_MENTION_RE` 只认「桌面 / 桌面版 / Windows 版」三种写法，
**手机版号没有任何断言守着** ✗ → 首页那处就静默过期了。
建议给 `scripts/lib/site-version.mjs` 加一条手机版号断言（首页 chip + 产品卡 + 下载页头部三处一致）✓。
