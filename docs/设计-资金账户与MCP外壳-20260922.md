## 一、资金账户（最小形态）

### 结论先说：**不新建账户表**

库里的钱**已经有三处记着、而且每条都带方式**：

| 已有表 | 记的是什么 | 方式字段 |
|---|---|---|
| `transactions` | 出库实收 / 退货退款 | `pay_method`（现金/微信/支付宝/其他） |
| `payments` | 客户还款 | `method` |
| `expenses` | 支出（房租/水电/运费/人工/杂项/进货付款） | `method` |
| `supplier_payments` | 付供应商 | `method` |

再建一张「账户表」= **第二份真相**（余额和流水迟早对不上，这是本项目反复治过的病）。所以：

- **账户 = 收款方式**（现金 / 微信 / 支付宝 / 其他）——就是现有 `pay_method` 的取值域，**一个新概念都不加**；
- **余额 = 期初 + Σ收 − Σ付**；
- **期初存进已有的 `settings` 表**（键 `account_opening`，值是一段 JSON）——**不新建表、不加迁移**。

### 口径（只写一次，界面与服务端逐例同输出）

- 只有 `selling_price` 非空的 `out` / `return` 才算现金移动（无售价的是渠道发货，不碰钱）。
- 出库实收 = `paid_amount ?? 售价 × 数量`（老库里 `paid_amount` 为 NULL 的语义是"全额付清"）。
- 退货按 `售价 × 数量` 记**付出**（与 `reports.js` 的 `todayPaymentSplit` 把退货记负是同一件事，这里分列收/付）。
- **金额为 0 的行不算一笔**（纯赊账 `paid_amount=0` 没有现金移动）。
- 方式没记的进「**未登记方式**」桶，**绝不摊到任何账户头上**，只报出来提醒补记。
- `sources`（销售/退货/还款/支出/付供应商）只统计**真的落进某个账户**的钱，与合计同口径。

### 一份口径、两份物理实现（这个项目既有的双胞胎套路）

| 位置 | 给谁用 | 为什么必须两份 |
|---|---|---|
| `electron/lib/moneyAccounts.js` | 给 `electron/commands/accounts.js`（HTTP/CLI/MCP）、以及 `loadAll` 读期初 | 打包只含 `electron/**`；`src/**` 不能进主进程 |
| `src/lib/moneyAccounts.ts` | 给桌面界面（本机模式没有服务端通道可调，只能本地现算） | 与 `restockAdvice` / `productName` 同一套路 |

**防漂移**：`src/lib/moneyAccounts.test.ts` 里有一段「双胞胎」测试，直接 `import` electron 那份，
把同一组输入喂给两边逐例比对结构是否完全一致 —— **改一边忘另一边，`vitest` 就红**。

### 暴露方式（刻意不新增 IPC 通道）

- 服务端：`electron/server.js` 的 `INVOKE_CHANNELS` 加
  - `fund:overview`（只读，`{from,to}` 可选日期区间）
  - `fund:setOpening`（写，同时登记进 `WRITE_CHANNELS` —— 否则只读/视图令牌也能改期初）
  - 命名用 `fund:` 而不是 `account:`：`account` 在这个项目里指**员工账号**（`AccountPage`），别混。
- 桌面端：**不新增通道**。期初随既有的 `data:loadAll` 一起下发（`electron/commands/catalog.js`），
  界面从 store 现算。新增 IPC 通道旧壳不认，这条路能走通就不该走那条。
- 界面：`src/components/MoneyAccountsCard.tsx`，挂在**支出记账页**（支出与资金是同一件事的两面）。

### 现场实测（中心库那份真库，2026-09-22 只读体检）

```
带方式的现金移动：只有 10 笔现金出库，合计 ¥78.60
payments / expenses / supplier_payments：三张表都是空的
```

**这不是 bug，是现状**：店里还没在开单/支出时记收款方式。所以这张卡现在的正确形态是
"把口径先立起来 + 没记的单独报出来提醒"——**它越用越准**，不是一上线就有大数。

## 二、MCP 外壳

### 为什么很薄

系统**早就有自描述的命令注册表**（不是为 MCP 新造的）：

- `electron/commandRegistry.json` —— 由 `scripts/command-surface.mjs --emit-registry` 从源码现算
  （`main.js` IPC + `server.js` HTTP/写标记 + `preload.cjs` 白名单 + `api.ts` 本机专属 + `commands/*.js` 的 JSDoc）；
- `GET /api/commands`（清单 / 单条 / 按前缀或关键词过滤）、`POST /api/command {name, params}`、`GET /api/agent`（接入说明）。

所以 MCP 这一层**没有实现任何新能力**，只做两件翻译：

1. 注册表 → MCP 的 `tools`（工具名把 `:` 换成 `_`，因为 MCP 工具名只允许 `[A-Za-z0-9_-]`）；
2. `tools/call` → 一次 `POST /api/command`。

### 安全默认（与项目立场一致：只读免确认）

- **默认只暴露只读命令**（注册表里 `write === false` 的 **108** 条）；
- 要暴露写命令必须显式 `--allow-write`（或 `FI_MCP_ALLOW_WRITE=1`）——
  写命令会改账/改库/改本机文件，不该由"接上就能用"的默认值打开；
- 两个自省工具：`inventory_command_doc`（查清单/说明）、`inventory_agent_guide`（取接入说明）。

### 零依赖

不引 `@modelcontextprotocol/sdk`：只用 node 自带能力实现 stdio 上的 JSON-RPC 2.0
（`initialize` / `notifications/initialized` / `ping` / `tools/list` / `tools/call`）。
多一个依赖就多一份要维护、要审计的东西；而这里要的协议面很小。

### 客户端怎么接

```json
{ "mcpServers": { "inventory": { "command": "node",
  "args": ["<仓库路径>/scripts/mcp-server.mjs",
           "--url", "https://app.junchengzn.com", "--token", "<中心库令牌>"] } } }
```

本机用（读 `%APPDATA%\fishing-inventory\server-token.txt` + `127.0.0.1:3200`）：
`node scripts/mcp-server.mjs --local`

## 三、顺手修的两处「机器说假话」

1. **`scripts/command-surface.mjs` 的 impl 误归因**（本次实测抓到的真缺陷）
   `inferImpl` 的点号分支原来**不看 `knownFns`**，于是 `cmds.productLabel(r)` 这种**纯格式化帮手**
   被当成了"这条通道的实现"——后果是 `ai:parseInboundNote` 与 `voice:transcribe` 两条通道的
   `impl` 都被挂成 `productLabel`，注册表判"说明串台"。判据已收紧为
   "只有命令层真的导出过的名字才算实现"。修完串台 = 0。
2. **注册表停留在 2026-09-16、指南里的数字也是旧的**
   重新生成后：**218 条命令 / 51 个前缀 / 108 条只读**（旧值 191 / 45 / 92）。
   `docs/进销存系统Agent接入指南.md` 与 `docs/命令接口-接口文档.md`（由 `gen-command-doc.mjs` 生成）同步更新。
   ⚠️ 注册表是**生成物**：改完通道一定要 `node scripts/command-surface.mjs --emit-registry`，
   否则 Agent/MCP 看到的是过期清单（比没有文档更糟）。

## 五、边界（没做、没验）

- **没有视觉验收**：资金账户卡片与「设置期初」对话框都没在真机上点过（过的是构建 + 断言）。
- **手机端没接**：`fund:overview` 服务端已可用，但手机端页面还没加这张卡（不归本线）。
- **MCP 没在真客户端（Claude Desktop / Cursor）里装过一次**：协议往返、生产库调用、工具清单都验了，
  但"某个具体客户端的配置写法"没实测（下面给了配置片段，第一次接的时候留意它的路径/参数写法）。
- **写命令默认关闭**这件事本身没做"人工确认弹窗"：开了 `--allow-write` 就等于放开写，慎用。
- **`fund:setOpening` 在「本机模式 + 旧壳」下还不行**：通道要下一个壳才进 preload 白名单；
  中心库模式（店里现在就是）走 HTTP 那条，已经能用。
