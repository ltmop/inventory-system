# 运维 Runbook：桌面端「局部更新」（B 通道 = 前端热更）

> 2026-09-15 落地。对应 `docs/桌面端更新方向-局部更新方案.md` 的 **P1**。
> 这份文档只讲**怎么发、怎么撤、出事怎么办**，不讲设计动机（那在设计文档里）。

## 一句话

改前端界面（`dist/**`）时，**不用再打 124MB 整包、不用退应用**：打一个 15MB 的热更包传到更新源，
收银机自己下好、校验好、提示一句「界面更新已就绪」，**由人点一下**才生效（重启进程约 2 秒）。

## 发一版前端热更（四步）

```powershell
cd C:\Users\Administrator\Desktop\库存管理\AI智能管理进销存系统

# 1) 改前端版本号（第四位 +1；壳版本不动）
#    public/web-version.txt 例如 1.1.8.0 → 1.1.8.1
notepad public\web-version.txt

# 2) 构建
npm run build

# 3) 发布前自检（不写任何文件；用**客户端同一套判据**校验，红了就别传）
node scripts/build-web-bundle.mjs --check

# 4) 生成 release/web/（latest.json + <版本>/**）并上传
node scripts/build-web-bundle.mjs
```

上传是**单独一步**（脚本只写本地 `release/web/`，绝不碰线上）：

1. 先备份线上目录（红线⑦：改服务器先备份再覆盖）。
2. 把 `release/web/` 整个传到静态目录 `web/` 下 —— 目标是 `web/latest.json` 与 `web/<版本>/**`。
3. 老版本目录**保留**（回退时要退回去），不要删。

> ⚠️ `latest.json` 里的 `baseUrl` **必须以版本号结尾**（如 `…/web/1.1.8.1/`）。
> 少了那一层不会在校验阶段报错，但**每一个文件都会 404** —— 真机验证时踩过，现在闸门会硬拦。

## 客户端这边会发生什么

| 时刻 | 行为 |
|---|---|
| 启动后 20 秒 | 静默取一次 `latest.json`（**每 6 小时最多一次**）。取不到/不合法 → 什么都不做 |
| 校验通过 | 逐文件准备到 `dataDir/web/<版本>.tmp/`：**本地已有的同内容文件直接复制**（比对"当前正在用的热更包/上一版/内置 dist"，**验过 sha256 才算一样**），其余才下载；每个文件验 sha256 与大小 |
| 全部通过 | 原子改名为正式目录，写指针 `dataDir/web-current.json` |
| 立刻 | 右下角提示「界面更新 vX 已就绪 → 点【立即生效】」 |
| 下次启动 | 加载新目录；页面挂载成功 → **转正**（`confirmedAt`） |
| 若没挂载成功 | 下次启动**自动退回上一版**，界面上给一句解释 |

四道护栏（缺一个都不上，逐条在 `electron/webUpdate.js` 里）：

1. **逐文件 sha256 + 原子改名**：任何一步失败就删 `.tmp`，正式目录与指针原样不动 —— 宁可没有热更，也不要半可用。
2. **转正与回退**：启动后 10 秒内页面没挂载出来就不算通过；下次启动自动退回上一版，**回退有界**（A→B→内置，不会无限循环）。
3. **只装业务层**：路径必须在目标目录内、后缀在白名单里、总量有上限；**并校验热更包引用的通道 ⊆ 当前壳支持的通道** —— 否则重演 2026-09-14 那 62 个通道的「点了没反应」。
4. **用户可见**：只提示、不静默替换；真的退回了也在界面上说明原因。

## 出事怎么办

| 情况 | 处置 |
|---|---|
| **怀疑热更包有问题**（还没生效） | 删掉更新源上的 `latest.json`。客户端拿不到清单就不动，退化为现状。 |
| **已经生效、界面不对** | 等它下次启动自动退回；或手动删 `%APPDATA%\fishing-inventory\web-current.json` 后重启 → 立刻回内置版。 |
| **只想在某一台机器上关掉热更** | 用 `FI_NO_WEB_UPDATE=1` 启动那个进程（临时），或删 `web-current.json`。 |
| **想强制回到内置版** | 删 `web-current.json` 与 `web/` 目录，重启。**数据完全不受影响**（热更只换页面文件，不碰数据库）。 |
| **想知道这台机器现在跑哪一版** | 看 `%APPDATA%\fishing-inventory\web-current.json`：`current.webVersion` 是热更版，`lastRollback` 是上次回退记录。 |

## 硬性边界（诚实三条）

1. **没有签名校验**。清单靠 HTTPS + 逐文件 sha256 保证**完整性**，不保证**来源**。
   也就是说：能改更新源的人就能改前端页面。这与手机线网页层热更的信任模型一致，
   但**不等于**安装包的签名强度。要更强就得给清单加签名（**还没做**）。
2. **主进程（`electron/**`）不在热更范围**。Node 没有安全的热重载，主进程改动走 A 通道（整包）。
   P1 只做 `dist`；`electron/commands/**` 是 P2。
3. **热更只在"已经装了带这段代码的壳"之后才可能发生**（这段能力本身要随 A 通道发一次）。
   老壳（≤1.1.8 已发布版）身上没有 `electron/webUpdate.js`，所以**线上目前处于休眠状态** ——
   在发下一版安装包之前，上传热更包不会有任何机器去取。

## 已跑过的验证（2026-09-15，真机）

- 闸门 `npm run check:webupdate` = **91 项全绿**（真跑四道护栏，含"坏包不留残留""回退有界"）
- 真机（本仓库 `npx electron .` 跑真 dataDir）：
  - 装 1.1.8.1（内容与内置 dist 等价，多一个 HTML 注释便于识别）→ **窗口**加载 `…\web\1.1.8.1\index.html`；
    **服务端 `/app`** 发出的 `index.html` sha256 = `c401e5cd…`（热更包那份），内置那份是 `29d1ef8e…`
    ⇒ 前置条件②「热更目录同时喂 `loadFile` 与 `webRoot`」达成
  - 挂载成功后 2.8 秒**转正**（`attemptedAt`→`confirmedAt`）
  - 故意装一个坏包 1.1.8.2（`index.html` 不引脚本）→ 未转正，`lastError` = 「首页 10 秒内未挂载」
  - 再启动一次 → **自动退回 1.1.8.1** 并转正，`lastRollback = {webVersion:"1.1.8.2"}`，
    主进程日志 `[webupdate] 已自动回退：v1.1.8.2 上次启动未通过渲染自检`

## 已知缺口（还没做）

- **没有签名校验**（见边界 1）。
- **设置页没有「检查界面更新」按钮**：目前只有启动后自动检查（6 小时节流）。想手动触发得靠 `webupdate:check` 通道。
- **P2（`electron/commands` 热更）与 P3（Feature Flag）没做**。
- **省流量的实测数字还没有**：机制已实现并过了闸门（"只有 index.html 变了 → 另一个文件确实没走网络"），
  但"一次真实 UI 修复到底下多少 MB"还没测。按文件构成**估算**：33 个文件里 28 个是壁纸（2 个 SVG 共 12.7MB）
  与字体，UI 修复时它们不变 → 实际下载 ≈ `index.html` + 变动的 JS/CSS（本次构建是 0.46MB + 2.50MB + 0.12MB）
  ≈ **3 MB**，而不是 15.3 MB。**这是估算，不是实测**，等第一次真实发版时把 `reused/bytes` 记下来补上。
