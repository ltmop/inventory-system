# 运维 Runbook：桌面端「局部更新」（B 通道 = 前端热更；C 通道 = 口径层热更）

> 2026-09-15 落地。对应 `docs/桌面端更新方向-局部更新方案.md` 的 **P1（B 通道）+ P2（C 通道）**。
> 这份文档只讲**怎么发、怎么撤、出事怎么办**，不讲设计动机（那在设计文档里）。

## 一句话

改前端界面（`dist/**`）或改账目口径（`electron/commands/**`）时，**不用再打 124MB 整包、不用退应用**：

| 改了什么 | 走哪条通道 | 用户感知 |
|---|---|---|
| 页面/样式/文案（`dist/**`） | **B 通道** | 秒级：下好 → 提示 → 点一下 → 重启约 2 秒 |
| 账目口径/命令逻辑（`electron/commands/**`） | **C 通道** | 同上（口径层要重启进程才生效，Node 不支持热重载） |
| 主进程/预加载/原生依赖 | **只能走 A 通道**（整包） | 退应用 → 装 → 重启，约 1 分钟 |

一个热更包**同时**带这两层（`codeFiles` 字段），所以一次发布两层一起更新。

## 发一版热更（四步）

```powershell
cd C:\Users\Administrator\Desktop\库存管理\AI智能管理进销存系统

# 1) 改前端版本号（第四位 +1；壳版本不动）
#    public/web-version.txt 例如 1.1.8.0 → 1.1.8.1
notepad public\web-version.txt

# 2) 构建（口径层不需要构建，它本来就是纯 JS）
npm run build

# 3) 发布前自检（不写任何文件；用**客户端同一套判据**校验，红了就别传）
node scripts/build-web-bundle.mjs --check

# 4) 生成 release/web/（latest.json + <版本>/**）并上传
node scripts/build-web-bundle.mjs
```

> **只想撤掉一个坏的口径层、页面照旧？** 用 `node scripts/build-web-bundle.mjs --no-code`：
> 清单里不带 `codeFiles`，客户端就把口径层回内置（页面部分仍然更新）。


上传是**单独一步**（脚本只写本地 `release/web/`，绝不碰线上）：

1. 先备份线上目录（红线⑦：改服务器先备份再覆盖）。
2. 把 `release/web/` 整个传到静态目录 `web/` 下 —— 目标是 `web/latest.json` 与 `web/<版本>/**`。
3. 老版本目录**保留**（回退时要退回去），不要删。

> ⚠️ `latest.json` 里的 `baseUrl` **必须以版本号结尾**（如 `…/web/1.1.8.1/`）。
> 少了那一层不会在校验阶段报错，但**每一个文件都会 404** —— 真机验证时踩过，现在闸门会硬拦。

## 客户端这边会发生什么

| 时刻 | 行为 |
|---|---|
| 启动后 20 秒 | 静默取一次 `latest.json`（**每 6 小时最多一次**）。取不到/不合法 → 什么都不做 |
| 校验通过 | 逐文件准备到 `dataDir/web/<版本>.tmp/`：**本地已有的同内容文件直接复制**（比对"当前正在用的热更包/上一版/内置 dist"，**验过 sha256 才算一样**），其余才下载；每个文件验 sha256 与大小 |
| 全部通过 | 原子改名为正式目录，写指针 `dataDir/web-current.json` |
| 立刻 | 右下角提示「界面更新 vX 已就绪 → 点【立即生效】」 |
| 下次启动 | 加载新目录；页面挂载成功 → **转正**（`confirmedAt`） |
| 若没挂载成功 | 下次启动**自动退回上一版**，界面上给一句解释 |

四道护栏（缺一个都不上，逐条在 `electron/webUpdate.js` 里）：

1. **逐文件 sha256 + 原子改名**：任何一步失败就删 `.tmp`，正式目录与指针原样不动 —— 宁可没有热更，也不要半可用。
2. **转正与回退**：启动后 10 秒内页面没挂载出来就不算通过；下次启动自动退回上一版，**回退有界**（A→B→内置，不会无限循环）。
3. **只装业务层**：路径必须在目标目录内、后缀在白名单里、总量有上限；**并校验热更包引用的通道 ⊆ 当前壳支持的通道** —— 否则重演 2026-09-14 那 62 个通道的「点了没反应」。
4. **用户可见**：只提示、不静默替换；真的退回了也在界面上说明原因。

## C 通道（口径层）额外三条 —— 它在主进程里执行代码，比页面层危险一档

| 护栏 | 做法 | 为什么 |
|---|---|---|
| **C1 绝不砖机** | 口径层在**启动时**被 `import`；任何加载失败都**静默回内置**（`electron/commandsLive.js` 里 try/catch） | 口径层坏掉顶多是"没热更"，**绝不能变成打不开** |
| **C2 出口集合校验** | 热更的 barrel 必须**导出内置 barrel 的全部名字**，缺一个就整包拒用 | 专拦"发布时打漏了文件"这类**一半新一半旧**；它比彻底坏掉更难查 |
| **C3 单入口** | 全仓库只有 `electron/commandsLive.js` 允许 import 命令层（闸门会断言） | 否则会出现两份口径同时活着：桌面端算一套、服务端算另一套 |

**口径层的包 = `electron/` 的一个子树**（不是只有 `commands/`）：`commands.js` + `commands/**` +
闭包里的 `license.js` / `channels.js` / `localSearch.js`。实测 35 个文件 / 208 KB，只依赖 Node 内置，
**零 `import electron`**（所以它才能被单独换掉）。发布脚本会自动算这个闭包。

> ⚠️ **C 通道的自动回退只覆盖"启动就能看出问题"的故障**（加载失败、导出不全、页面挂载失败）。
> **运行期才炸的错误不会自动回退** —— 要靠人发现，然后用 `--no-code` 发一版撤掉它。

> ⚠️ 口径层热更目录里那个 `package.json`（`{"type":"module"}`）是**客户端自己生成**的
> （`%APPDATA%` 下没有它，`.js` 会被 Node 当 CommonJS，ESM 语法直接报错）。
> 清单里带 `package.json` 会被**拒绝**——即不让更新源决定模块解析方式。

## 出事怎么办

| 情况 | 处置 |
|---|---|
| **怀疑热更包有问题**（还没生效） | 删掉更新源上的 `latest.json`。客户端拿不到清单就不动，退化为现状。 |
| **已经生效、界面不对** | 等它下次启动自动退回；或手动删 `%APPDATA%\fishing-inventory\web-current.json` 后重启 → 立刻回内置版。 |
| **只想在某一台机器上关掉热更** | 用 `FI_NO_WEB_UPDATE=1` 启动那个进程（临时），或删 `web-current.json`。 |
| **想强制回到内置版** | 删 `web-current.json` 与 `web/` 目录，重启。**数据完全不受影响**（热更只换页面文件，不碰数据库）。 |
| **想知道这台机器现在跑哪一版** | 看 `%APPDATA%\fishing-inventory\web-current.json`：`current.webVersion` 是热更版，`lastRollback` 是上次回退记录。 |

## 硬性边界（诚实四条）

1. **没有签名校验**。清单靠 HTTPS + 逐文件 sha256 保证**完整性**，不保证**来源**。
   要更强就得给清单加签名（**还没做**）。
2. **B 通道**改的是沙箱里的页面（受 preload 通道白名单约束）；
   **C 通道改的是主进程里的代码** —— **能改到更新源的人就能在这台机器上执行任意代码**。
   这与手机线网页层热更的信任模型一致，但**不等于**安装包的签名强度。
   这是引入 C 通道时最大的代价，写在这里是为了不假装它不存在。
3. **主进程其余部分（`main.js` / `preload.cjs` / 原生依赖）不在热更范围**。Node 没有安全的热重载，
   这类改动走 A 通道（整包）。热更范围严格限定为 `dist/**` + `electron/` 的那个闭包子树。
4. **热更只在"已经装了带这段代码的壳"之后才可能发生**（这段能力本身要随 A 通道发一次）。
   老壳（≤1.1.8 已发布版）身上没有 `electron/webUpdate.js` 与 `commandsLive.js`，
   所以**线上目前处于休眠状态** —— 在发下一版安装包之前，上传热更包不会有任何机器去取。

## 已跑过的验证（2026-09-15，真机）

闸门 `npm run check:webupdate` = **159 项全绿**（真跑护栏：坏包不留残留 / 回退有界 / **口径层真的被 ESM 加载起来** /
加载失败静默回内置 / **纯 Node 下也 import 得动**）。

真机（本仓库 electron 跑真 dataDir，假更新源在 127.0.0.1）：

- **B 通道**
  - 装 1.1.8.1 → **窗口**加载 `…\web\1.1.8.1\index.html`；**服务端 `/app`** 发出的 `index.html`
    sha256 = `c401e5cd…`（热更包那份），内置那份是 `29d1ef8e…` ⇒ 前置条件②达成
  - 挂载成功后 2.8 秒**转正**
  - 故意装坏包（`index.html` 不引脚本）→ 未转正，`lastError` =「首页 10 秒内未挂载」
  - 再启动 → **自动退回上一版**并转正，主进程日志有回退原因
- **C 通道**
  - 装一个"改过的口径层"（给 `analyticsOverview` 加一个可观察字段）→ 启动日志
    `[commands] 口径层来自热更：…\code\1.1.8.1`；**走 server.js 那条路**取
    `GET /api/analytics/overview` 真的返回了那个标记 ⇒ **单入口成立**（桌面端与服务端拿到同一份）
  - 2.3 秒转正；真实数据不受影响（324 SKU / 7609 件）
  - 故意装一个**语法坏掉**的口径层 → 应用**照常启动**（4 进程、17532/17533 都在），
    日志 `热更口径层未启用：…Unexpected end of input`，接口回到内置实现，
    状态里 `codeDir: null`。**没有砖机**
  - 期间抓到并修掉一个真 bug：口径层的放弃原因原本写进 `lastError`，
    会被页面自检转正时的 `markHealthy` 清成 `null` → owner 永远看不到原因。
    现在用独立字段 `lastCodeError` + `lastCodeErrorAt`，并已验证在转正后仍然保留。
- **省流量（实测，不再是估算）**：一个同时含两层的包 = 68 个文件，
  实际**只下载 6,655 字节（6.5 KB）**，其余 67 个文件 / **15.5 MB 本地复用**
  （`reason` 里写着"其中 67 个文件本地已有、省下 15.5 MB"）。
  对比：整包 124.7 MB、只发前端 15.3 MB。验收指标「<500KB」达成。

## 已知缺口（还没做）

- **没有签名校验**（见边界 1、2）。
- **口径层的运行期错误不会自动回退**（只有启动期能发现的故障才会）—— 撤法是发一版 `--no-code`。
- **设置页没有「检查更新」按钮**：目前只有启动后自动检查（6 小时节流）。想手动触发得靠 `webupdate:check` 通道。
- **P3（Feature Flag）没做** —— 它比 C 通道更安全（秒级回滚、不发版），优先级本应高于 C。
- **没有"C 通道真机演练单"**：第一次真实发版时按上面的步骤走一遍，把 `reused/bytes` 记进台账。
