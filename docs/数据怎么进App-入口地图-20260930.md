# 数据怎么进 App：入口地图

日期：2026-09-30
问题来源：老板问「怎么才能把数据接入到 APP 里呢」

状态：**只读取证，未改任何实现代码。**

---

## 一、一句话答案

**这个系统的数据只有一道门：`electron/commands/*.js` 里那 218 条命令。**

手机是网页（PWA）、电脑是 React，两边看起来完全不同，但最后都打同一个洞：

```
POST /api/invoke?token=<设备令牌>
body: { channel: 'supplier:pay', payload: { … } }
```

谁都逃不掉。想让任何东西写进库，就得调一条命令。

---

## 二、数据流（五级）

| 级 | 环节 | 在哪 | 证据 |
|---|---|---|---|
| ① | 谁来说话 | 人 / 扫码枪 / 摄像头 / 麦克风 / Excel / 外部程序 | — |
| ② | 唯一入口 | `POST /api/invoke?token=…`（也接受 `/api/command`） | `server.js:1953`、`server.js:1773` |
| ③ | 218 条命令 | `electron/commands/*.js`，清单在 `commandRegistry.json` | 全库唯一写库路径 |
| ④ | 落库 | SQLite `data.db`（`node:sqlite` + WAL） | `db.js:1-10` |
| ⑤ | 云同步 | `cloudSync` → `sync.junchengzn.com` | `app.js:336`、`cloudSync.js` |

**关键推论：只要会发 HTTP、拿得到 token，任何东西都能往里写数据。**
这条链路是通的，不是今天要修的。

## 三、十条通道，哪些通的哪些死了

| # | 通道 | 现状 | 能用吗 | 代价 / 备注 |
|---|---|---|---|---|
| ① | 手敲（手机 / 电脑） | 已有 | ✅ 唯一在用 | 每天十几分钟 —— 老板嫌的就是这个 |
| ② | 扫商品条码 | 已有 | ✅ | `pos.js` 真扫码，但**得先把货建进档案** |
| ③ | 拍照 → AI 认单据 | 已有 | ✅ 几乎零开发 | `ai.js:420 parseInboundNote` 已实现 |
| ④ | 语音报单 | 已有 | ✅ | `ai.js:1070 transcribeAudio`；门店嘈杂+方言，场景受限 |
| ⑤ | Excel / CSV 批量导入 | 已有一半 | ⚠️ 要补命令 | `commands/import.js importBatch` **只吃商品+批次**，支出/流水没有 |
| ⑥ | HTTP 命令总线 | 已通 | ✅ 随时能写 | `/api/invoke` + token |
| ⑦ | Agent 接口 | 已通 | ✅ 随时能写 | `server.js:1858 agentManifest()`、路由 `/api/agent` |
| ⑧ | 微信/支付宝账单**自动**同步 | 没有 | ❌ **做不到** | 个人收款码官方不给第三方开接口（平台规则） |

| ⑩ | 聚合收款码回调 | 要新建 | ⚠️ 唯一真自动 | 收钱吧/拉卡拉：营业执照+商户号+常驻服务端 |

## 四、落到「钱出去」这件事：三条能走的路

| | A 拍一张 | B 导一次 | C 接一条 |
|---|---|---|---|
| 工时 | **半天** | 1~1.5 天 | 1.5~2 周 |
| 做法 | 摄像头拍进货单/付款截图 → `parseInboundNote` 认 → 生成 `supplier:pay` | 导出账单 Excel → 新增导入命令 | 换聚合收款码 → 回调自动落流水 |
| 老板要做什么 | 掏手机拍一张（他本来就在拍） | 每月导一次文件 | 什么都不用做 |
| 代价 | 几乎零新增接口 | 要他记得导 | 费率 0.25%~0.38% + 要执照 |

**推荐顺序：A 先做。** 它不需要任何外部接口，且老板"拍照留底"这个动作本来就存在。

### 死路（别承诺）

> **实时自动同步私人收款码 —— 做不到。**
> 个人收款码不向任何第三方开放流水接口，这是平台规则，不是我们技术不够。
> 上一轮已定：**不要对客户说「以后能自动同步」**，答应了收不回来。

## 五、一个必须纠正的事实

**手机端的「支出记账 / 供应商 / 报损 / 盘点 / 客户欠款 / 收款登记」早就做好了。**

页面都在 `electron/mobile/pages/`：`expenses.js`、`suppliers.js`、`waste.js`、`stocktake.js`、`customers.js`、`receipts.js`、`restock.js`、`expiring.js`。

入口在 `electron/mobile/app.js` 第 1946–1961 行的功能列表里，例如：

```js
{ icon: 'wallet',   t: '支出记账', d: '记一笔房租 / 水电 / 进货', fn: () => navigate('expenses') }
{ icon: 'truck',    t: '供应商',   d: '进货对账',                fn: () => navigate('suppliers') }
```

**它们埋在「更多」的第四层。** 所以问题从来不是"数据接不进来"，而是：

> **路早就修好了，没人走 —— 客户根本没找到入口。**

下一版真正要动的，是把这条路摆到他眼前，而不是再挖一条新路。

## 六、动手位置速查

| 要改什么 | 改哪 |
|---|---|
| 新增一种数据来回 | `electron/commands/<新命令>.js` + 注册进 `commandRegistry.json` |
| 手机端加入口 | `electron/mobile/pages/<页面>.js` + `app.js` 功能列表/Tab |
| 桌面端加入口 | `src/pages/<页面>.tsx` |
| 校验 / 限流 / 鉴权 | `server.js:1963` `rateLimited` |
| Agent 可见能力清单 | `server.js:1858 agentManifest()` |
