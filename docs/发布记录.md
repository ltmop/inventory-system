# 发布记录（安装包 ↔ 提交 对照表）

> 为什么要有这张表：2026-09-12 手工 bump 出过一个 `1.0.11` 安装包，但那次 bump **没有落进任何提交**
> ——`package.json` 停在 `1.0.10`、`package-lock.json` 停在 `1.0.11`，两边互相矛盾。
> 结果是「这个安装包到底对应哪份代码」查不出来，只能靠时间戳猜。
> 安装包本身在 `.gitignore` 里（`release/`），所以**指纹必须记在这里**，否则换台机器就断了线索。

## 怎么发（三个文件必须一起传）

```
npm run dist
```
产出并自动校验：
- `release/AI智能进销存系统 Setup <版本>.exe`
- `release/AI智能进销存系统 Setup <版本>.exe.blockmap`
- `release/latest.yml` —— **应用内更新读的就是它**，`dist.cjs` 会当场校验它的 `version`
  与 `package.json` 一致、且指向本次构建的那个 exe，不一致直接中止（防自动更新到错版本）

发布 = 把这三个文件传到更新源。只传 `.exe` 的话应用内更新不生效。

**注意**：NSIS 安装包的字节**不可复现**（内嵌构建时间戳等），所以同一份代码重打两次 sha256 会不同。
sha256 用来核对「传上去的包和本地打的是不是同一个」，不是用来标识源码版本的 —— 源码版本看 `提交` 列。
