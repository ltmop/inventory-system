## 四、五条铁律（违反 = 事故）

1. **打包选包按时间戳**——dist.cjs 复用临时目录，find 带 mtime 条件
2. **兜底口径 = 主路径口径**——AI 建议/纠错不得改变记账/搜索口径（orchestrator 已守）
3. **加密失败宁抛错不降级**——大数组分块
4. **发布前验证发布配置**——publish.url / appId 一致性
5. **改源码不改产物**——src/ 才是源

## 五、已验证但容易踩的坑（上几轮实测）

| 坑 | 处理 |
|----|------|
| **Playwright 模拟 React 受控输入不可靠** | fill() 也未必触发 setKeyword；钩子逻辑用「分层验证」：IPC 通道 ✓ + smartSearch 逻辑 ✓ + find 匹配 ✓ + tsc ✓，别依赖 UI 自动化断言钩子触发 |
| **KWS/TTS 测试概率性偶发**（5 次内检出） | 偶发 ✗ 重跑即绿，是环境音频问题非代码 bug |
| **PowerShell 引号地狱** | node -e 里带 `$`/`\1` 会被吞；用 write 工具写临时脚本文件再跑 |
| **ssh 密钥** | 用 `skey-junchengzn.pem`（adjczn 已被服务器拒） |
| **官网版本号更新** | 用 node 正则替换，**别用 bash sed 反向引用**（$1 被 shell 展开曾改坏链接） |
| **改服务器代码前先 diff** | 旧版覆盖新版是最大事故源（复盘 3.4 有记录） |

## 八、给接手 Agent 的三句话

1. **别重新发明**：orchestrator/本地兜底/发布链都做好了，你负责「让用户看见 AI」而不是再造 AI。
2. **先测基线再动手**：`node scripts/test-backend.mjs`（592 断言）是底线，每步改动后跑它。
3. **AI 是能力不是页面**：任何「把 AI 藏进独立页/设置」的冲动都是倒退——用户打开就得看见、随手就能用。
