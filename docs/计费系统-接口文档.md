# 计费系统接口文档（P0 计费阀门 v1）

> 实现：`ai-server-src/`（config / quotaStore / deviceRegistry / billingProxy / quotaRoutes + server.js 挂载）
> 客户端统一入口：`electron/aiQuota.js`。测试：`ai-server-src/tests/quota.test.js`（17 个，node --test）。

## 一、总约定

- **余额口径**：`remaining = Σrecharge_log − Σusage_log`，按账户（account_key）聚合。账户 = 激活码（已绑定）或 `dev:<deviceToken>`（匿名试用）。
- **防虚报**：token 数以网关从上游响应 `usage` 实读为准，客户端自报字段一概不采信；上游缺 `usage` 时按字符数估算（≈2 字符/token，宁高勿低）并打 `estimated=1` 标记。
- **402 语义**：`remaining <= 0` 时网关一次都不放行、不调上游，直接返回 HTTP 402。剩余 >0 的调用放行，超额部分扣到 0 为止。
- **幂等**：客户端每次请求生成 `idempotencyKey`（UUID）。网关 `usage_log.idempotency_key` UNIQUE，同 key 重发返回缓存结果（`cached: true`），不重复扣费。
- **故障策略**：计费存储故障（`BillingUnavailable`）→ 全部新端点 503，**宁可误断不可漏计**。现有端点（/ai/chat、/ai/vision、/api/store/* 等）不受影响。
- **功能名常量**（`config.js` / `aiQuota.js` 双端同步，禁硬编码）：
  `agent_chat`（AI 对话）/ `daily_summary`（打烊日报）/ `correct_term`（语音纠错）/ `connection_test`（连通测试）
- **流水字段**（硬规范）：`timestamp, deviceToken, feature, model, inputTokens, outputTokens, totalTokens, latency`（+ `estimated` 标记）。

## 二、端点

### 1. POST /api/v1/device/register — 设备注册
请求：
```json
{ "licenseKey": "ADU-FISH-... (可选)", "deviceName": "门店电脑 (可选)", "fingerprint": "机器指纹 (可选)", "deviceToken": "已有凭证 (可选，重绑/迁移用)" }
```
响应 200：
```json
{ "ok": true, "deviceToken": "<64位hex>", "quota": { "total": 150000, "used": 0, "remaining": 150000 }, "trialGranted": true, "migrated": false, "bound": false, "suspect": false }
```
规则：
- 新账户首次注册赠试用额度 `TRIAL_QUOTA`（默认 150000 tokens ≈ 100 次），每账户只赠一次。
- `licenseKey` 走 Ed25519 验签（客户端同枚公钥），伪造码 → 403 `invalid-license`。
- 匿名设备（无激活码）试用绑 `dev:<token>`；后续带 `deviceToken + licenseKey` 重注册 → 余额迁移（`migrated: true`），试用不重复赠。
- 已绑激活码 A 改绑 B：A 的历史消耗留在 A，B 作为新账户赠试用。
- fingerprint 软信号：同一指纹 30 天内注册 >3 个 deviceToken → `suspect: true`，不硬拦。

### 2. POST /api/v1/ai/proxy — AI 代理调用（核心）
请求：
```json
{ "deviceToken": "...", "feature": "agent_chat", "messages": [...], "maxTokens": 600, "tools": [...], "idempotencyKey": "uuid" }
```
响应 200：
```json
{ "success": true, "message": { "role": "assistant", "content": "..." }, "usage": { "prompt_tokens": 100, "completion_tokens": 50, "total_tokens": 150 }, "remaining": 149850 }
```
错误：
| HTTP | body | 场景 |
|------|------|------|
| 402 | `{ success:false, code:402, message:"余额不足", remaining }` | 余额耗尽，未调上游 |
| 502 | `{ success:false, code:502, message }` | 上游超时/5xx/空响应，**不扣费** |
| 503 | `{ ok:false, reason:"billing-unavailable" }` | 计费存储故障，**不扣费** |
| 401 | `{ success:false, code:401 }` | deviceToken 无效（客户端清缓存重注册） |
| 400 | `{ success:false, code:400 }` | 参数缺失/未知 feature |

行为顺序：校验 → 幂等重放检查 → 402 闸门 → 转发上游（model 强制用网关配置，客户端无权指定）→ 实读 usage 记账 → 返回。

### 3. GET /api/v1/ai/quota?deviceToken=xxx — 余额查询
```json
{ "ok": true, "total": 150000, "used": 300, "remaining": 149700, "packageType": "trial", "expiresAt": null, "bound": true }
```

### 4. GET /api/v1/ai/usage?deviceToken=xxx&limit=20 — 流水查询
```json
{ "ok": true, "items": [ { "timestamp": "...", "deviceToken": "...", "feature": "agent_chat", "model": "deepseek-chat", "inputTokens": 100, "outputTokens": 50, "totalTokens": 150, "latency": 812, "estimated": false } ] }
```

### 5. POST /api/v1/admin/recharge — 人工充值（第一期不接在线支付）
鉴权：请求头 `x-admin-key: <ADMIN_KEY>`（或 body.adminKey）。未配置 ADMIN_KEY → 503。
```json
{ "licenseKey": "ADU-FISH-... 或 deviceToken", "amount": 50000, "packageType": "次包 | 月包", "note": "微信收款 50 元" }
```
响应：`{ ok:true, recharge: {...}, quota: { total, used, remaining } }`
- 支持给**尚未注册设备的激活码**预充值，注册时余额即到账。
- 只给 deviceToken 时充到该设备当前账户（匿名设备充 dev: 账户，绑定后建议改用 licenseKey 充值）。

## 三、客户端配套

- `electron/aiQuota.js`：`consumeViaGateway(feature, messages, opts)` / `recordLocalUsage(db, feature, usage, channel)` / `bindLicense(code)` / `gatewayQuota()` / `gatewayUsage(limit)`；`FEATURES` 常量；deviceToken 与激活码原文 safeStorage 加密落盘（`device-token.enc` / `license-code.enc`）。
- `electron/ai.js`：`chatRaw` gateway 分支改经 aiQuota；BYOK 分支直连不变 + 本地记账钩子。402 上抛为 `{ ok:false, reason:'quota-exceeded', code:402, remaining }`，聊天面板显示充值引导。
- `electron/db.js`：新增 `ai_usage_log`（feature/model/input_tokens/output_tokens/channel/created_at，纯追加）。旧 `ai_usage`（每日次数配额）不动。
- IPC 新增：`ai:gatewayQuota` / `ai:gatewayUsage` / `ai:localUsageStats` / `ai:bindLicense`（游客模式黑名单含 bindLicense）。
- 「AI 智能」页：GatewayQuotaCard（余额/本月已用/功能占比/最近 20 条流水/去充值弹窗/未绑定激活码引导输入框）。

## 四、部署（网关）

环境变量（在现有基础上新增）：
```
QUOTA_DB_FILE   计费库路径，默认 <网关目录>/quota.db
TRIAL_QUOTA     试用额度 token 数，默认 150000
ADMIN_KEY       人工充值密钥（必填，未配置则充值端点 503）
```
步骤：把 `ai-server-src/` 整个目录上传覆盖 → 装好环境变量 → 重启进程。存储层优先用 `node:sqlite`（Node ≥ 22.5），老 Node 自动降级同目录 `quota.json`（接口不变）。部署后用 `/health` + 一次 register/quota  curl 冒烟。

## 五、已知边界

- 现有 `/ai/chat`、`/ai/vision`（手机 APP 共用连接码）按任务书保持原样，手机端 P0 不记账（CEO 已确认，后续版本收口）。
- `expiresAt` 恒为 null：次包/月包有效期后续版本实现。
- 客服微信号 `SERVICE_WECHAT` 在 `GatewayQuotaCard.tsx` 顶部常量，上线前替换为真实号。
