# 进销存系统 1.0 正式版 · 全面升级任务计划书

> 从 v0.4.1 → v1.0.0 的全链路升级计划。
> 覆盖：架构 → UI → 前端 → 后端 → 全栈 → 布局 → 动效 → 打包上服务器。
> 原则：**AI 是能力不是页面**；**用户关心什么就显性什么**；**不重写，重构+增强**。

## 一、架构升级（地基，先做）

### 1.1 分层演进（不推翻现有，加边界）

```
现状: UI(src) → IPC(preload/main) → commands → SQLite
目标:
  UI 层   → 页面 + AI 浮层 + 全局语音
  命令层  → commands/（复用，加"可插拔 AI 钩子"）
  服务层  → 新增 ai-orchestrator（本地+云端 AI 统一出口）
  数据层  → SQLite/WAL + 备份三份（本地/第二位置/云）+ 审计
```

- **AI 编排层（新增 ai-orchestrator.js）**：统一封装 agentChat/语音/拍照/模糊搜索 → 前端不再散调各 AI 模块
- **钩子点（关键）**：outbound 扫码 miss 时挂 AI 兜底、inbound 拍照识别、search 模糊纠错 —— 不动主链路，只在"兜底"处接 AI（复盘铁律：兜底口径=主路径）

### 1.2 可集成开源（GitHub 调研结论）

| 开源项目 | 价值 | 集成方式 | 优先级 |
|---------|------|---------|--------|
| mateopiza/ai-point-of-sale | AI+离线优先 POS 的交互范式参考 | 参考其"AI 兜底录入"设计，不引依赖 | 参考 |
| lithiaa/pos-electron | Electron POS 打包/多窗口模式 | 参考打包配置 | 参考 |
| BizzAI (orion-ai) | MERN POS：快速开单/PDF 发票 | 发票导出参考（现有 exceljs 已有，补 PDF） | 低 |
| voicepower-pos | 本地语音开单 PoC（Vosk+LLM） | 思路验证：本地 ASR 已用 sherpa，够用 | 参考 |
| 自研为主 | 系统已 0.4.1 很完整，开源只做**参考和补漏**，不重写 | | |

> 结论：**不引入大型开源依赖**（避免架构重写风险），只参考其交互范式 + 补 2 个缺口（PDF 发票、AI 兜底 UX）。

## 九、顾问评审修订（2026-09-01 · 周掌柜评审后吸收）

> 四项决策全部按推荐确认；以下 5 个窟窿补入计划。

### 9.1 验收红线：自家店真实跑账（最重要，优先级最高）

**1.0 发布前的硬性验收（比 Playwright 走查值钱十倍）**：
- 自家店真实数据录入（8/10 之后断的货补录进系统）
- 每天开单走系统，**连续真实运行 2 周**
- 期间账实相符：库存/毛利/应收/现金 与老板手工账对得上
- 验收标志：沉睡榜不再 100% 全红、首单状态真实更新

> 这是「1.0 是功能齐还是店里真能用」的分水岭。代码再漂亮，货不进系统、单子不走系统，1.0 就是给空气发布。

### 9.2 语音依赖链（openssl）——已完成，标注即可

顾问指出语音要 HTTPS、HTTPS 要 openssl、本机 openssl 不在 PATH——**该问题已在上轮 A2 解决**：
- electron/tls.js 已实现 findOpenssl()：C:/D: 盘 Git 路径自动探测
- 实测命中本机 D:\Git\usr\bin\openssl.exe，证书生成 ok:true（commit 679ab89）
- **计划书动作**：M1 不再重复开发，只做「语音端到端实测」（喊小杜→识别→答复，走 HTTPS）

### 9.3 模糊搜索降级路径：本地算法兜底优先，AI 只做增强

AI 兜底依赖豆包/DeepSeek KEY——**断网/无 KEY 时不能哑**：
- 模糊搜索：**本地算法兜底优先**（拼音/子串/编辑距离），AI 纠错只做增强
- 拍照识别：无 KEY → 明确提示「识别不可用，手动录入」而非卡死（现有降级已如此，1.0 守住）
- 语音：本地 ASR（sherpa）不依赖云端，断网可用（现状已满足）
- **验收**：断网 + 无 KEY 场景下，扫码 miss → 模糊搜索/手动录入仍可用，不卡死

### 9.4 「3 秒开单」先测基线

3 秒是口号不是标准——**M1 先实测当前基线**（扫码→锁品→数量→收款→完成 实际几秒），再定 1.0 目标。目标：相比基线优化可量化的秒数。

### 9.5 PDF 发票：砍掉，省工期

渔具店客户要的是热敏小票 + 微信/支付宝收款；PDF 增值税发票是对公/月结客户才要——**暂无此客户群，1.0 不做 PDF 发票**。省出的工期给「客户对账单+按单核销」（第二档，更值钱）。

### 9.6 工期调整

- M4 动效**并入 M2**（M2 变 3.5~4 天含 buffer）
- 总工期：M1(2) + M2(4) + M3(2) + M5(1) ≈ **9 天**（M4 并入 M2）

### 9.7 官网 APK 清理（别让旧坑长回来）

官网 download 手机 APK 还是 0.1.0 老包——1.0 发布时**同步更新或下架**，别让客户装到三年前的版本。
