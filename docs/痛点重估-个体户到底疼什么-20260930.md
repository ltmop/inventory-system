# 痛点重估：个体户门店老板到底疼什么

日期：2026-09-30
触发：老板复核上一轮《三步台阶》后的判断 —— **「能用，但对个体户门店老板来说不算痛点」**

状态：**结论先行 —— 暂停为这批个体户改任何实现代码，先做客戶筛选。**

---

## 一、上一次错在哪

上一版方案的全部精力，花在**让「记录」变便宜**：从录商品压到一个悬浮键两个字段。

但老板的问题不是"记录太贵"，是**"记录没用"**。

> 记录的价值在**未来**兑现（月底盘账、年底算总账）；
> 个体户只为**今天**买单。
>
> 微信给的是当下就有的答案（收工打开就有数字），我们要他做的是给未来存档案。
> 这不是升级，这是让人先干活、好处以后再说 —— 哪怕是十秒钟的活。

**所以：任何围绕"怎么让他记录"的优化，做得多好都不痛。方向错了。**

---

## 二、痛点判定铁律（以后所有判断都用这条）

> **这件事今天不做，我今天会不会吃亏？**
>
> 会 → 痛点。
> 不会 → 只是道理，客户嘴上会说"挺好的"，但不会打开第二次。

用这条尺子，把上一版台阶逐个过：

| 上一次给的东西 | 老板的真实感受 | 判定 |
|---|---|---|
| ① 速记「只记钱不记货」 | 和微信一样省事，但拿到的数也和微信一样 —— **那我用它干嘛** | ❌ 不是痛点（有替代品） |
| ② 赊账欠款管理 | 一周也就两三笔，本子记一笔 / 微信备注一下也能对付 | ⚠️ 弱痛点（量大才成立） |
| ③ 毛利 / 压货分析 | 数据好看，但看完不改变我今天做什么 | ❌ 是道理，不是疼痛 |

结论：**三条全部停在"有用"这一档，没一条落在"疼"这一档。**

---

## 三、个体户真正在疼的四件事（按疼度排）

筛选条件同时满足三条：**频率高 + 微信替不了 + 我们做得到**。

| # | 疼在哪 | 老板的原话 | 频率 | 微信能否替代 |
|---|---|---|---|---|
| 1 | **钱出去的方向是黑箱** | 「上个月明明赚钱了，卡里咋没多？」 | 每天/每周 | ❌ 微信只记进，不记出（进货、房租、工钱全是分散转账和现金） |
| 2 | **当场说不清，就要吃亏** | 熟客说「我上次给过钱了」；拿不出小票只能自认倒霉 | 每周 | ❌ 缺的是**凭证**，不是账本 |
| 3 | **断货丢单 / 压货压钱** | 「这个竿早该进了，客人白来一趟」「这一架子压了半年钱」 | 每周 | ❌ 微信完全不知道你有多少货 |
| 4 | **低频剧痛**：盘点、报税、给合伙人/家里交代 | 一年几次，一次骂一次娘 | 低频高烈度 | ❌ |

**第 2 条最容易被忽略，但最值钱：账目是对未来的交代，凭证是当下的武器。**
个体户愿意为"当场能拿出来打脸的东西"付钱，不愿为"月底能算清楚的系统"付钱。

---

## 四、最疼的那件事我们接不住（诚实止损）

**客流不稳 / 没人进店 / 老客不来** —— 这是个体户排在**第一**的痛，比上面四条都疼。

但这不是进销存能解决的，是选址、品类、短视频和私域的活。
**不要为了拿下客户去硬蹭这条**，答应了收不回来，还会把产品做歪。

---

## 五、10 秒客户筛选（改代码之前必须问完）

两句话，比改两星期值钱：

| 问题 | 答「不是」意味着 |
|---|---|
| **① 你雇人看店吗？（或家里人替你看？）** | 没人看店 = 他自己就是账本，脑子+微信的组合永远打不过 App，别花力气 |
| **② 你上个月进货掏出去多少钱，能张口说出来吗？** | 能张口 = 支出他心里有数，不痛；说不出来 = 第 1 条痛点成立 |

- 两个都答不上来 → **真买家**，可以在「支出/凭证/压货」三条里找钩子
- 只要有一个答"没问题/能记住" → **现在不是买家**，留个联系方式，别改代码

> 上一版说"取决于有没有赊账"，这次改口径：**赊账不够格当分水岭**（可替代），**有没有雇人看店 + 支出清不清楚**才是。

## 六、结论与下一步

1. **不为这批个体户改任何实现代码**，直到上面两个问题有答案。
2. 拿到了"是真买家"的答案，才回来从表格第 1/2/3 条里挑**一条**做，不是三条都做。
3. 上一轮定的 3 天排期（速记入口 / 欠款屏 / 文案）**作废**。
4. 上一版文档 `docs/客户弃用-诊断与三步台阶-20260930.md` **保留作为"此路不通"的记录**，别删，避免下次重蹈。

# 七、转向：别让他录收入，让他录支出（2026-09-30 追加，整份文档的最终结论）

老板复核确认：**整套三步台阶都不成立**（不只是某一条）。整条"让他记录"的路作废，从
「钱出去的方向」重起。下面是新结论。

## 7.1 为什么是支出，而不是收入

同一个动作（录一笔），放在收入侧是地狱，放在支出侧是平地：

| | 收入（卖货） | 支出（进货/房租/工钱） |
|---|---|---|
| 一个月多少笔 | 几百~上千笔 | **十几笔** |
| 单笔金额 | 几十块 | **几千~上万** |
| 谁经手 | 店员/家人也可能收 | **老板自己亲手付** |
| 微信能不能替 | ✅ 微信账单全都有 | ❌ 只看到转出去一个数，**不知道这批货回没回本** |
| 不记会怎样 | 微信已经记了 | **"明明赚钱了，卡里咋没多"** |

**结论一句话：别跟他抢收入，收入是微信的地盘；支出是黑的，而且一个月才十几笔，他记得住也愿意记。**

## 7.2 好消息：这套东西代码早就写好了

不用重做，只需要把它从"更多"里搬到手机首页：

| 已有命令 | 干什么 | 对应痛点 |
|---|---|---|
| `supplier:create` / `supplier:pay` / `supplier:payments` / `supplier:statement` | 建供应商、登记付款、看付款流水、拉对账单 | **① 支出黑箱** |
| `waste:create` / `waste:list` / `waste:summary` | 报损登记与汇总（碎竿、断线、丢货） | **① 钱漏出去** |
| `stocktake:create` / `submit` / `updateItem` / `complete` | 盘点全流程 | **④ 低频剧痛** |
| `report:restock` / `report:lowStock` | 该进什么、哪些快断货 | **③ 断货丢单** |
| `analytics:stockValue` / `report:hotSellers` | 库里压了多少钱、什么真好卖 | **③ 压货压钱** |

> 证据来源：`electron/commandRegistry.json`（共 218 条命令，以上均已注册可用）。
> 桌面端入口：`src/pages/SuppliersPage.tsx`、`src/pages/WastePage.tsx`。
> **`supplier:pay` 这条最值钱** —— 它是唯一的"钱出去"落库路径，且完全不依赖销售端的商品录入。

## 7.3 手机上只放一块：今天到底落了多少钱

不要做报表，做一块每天抬头就看见的板：

```
┌──────────────────────────────┐
│ 今天                          │
│ 收   486.00   ← 23 笔·来自收银台 │
│ 付   0.00    ← 今天还没掏钱     │
│ ─────────────────────────── │
│ 本月到手   [ 5,180.00 ]       │
│ 收 30,200 · 付 24,000 · 损耗 1,020 │
└──────────────────────────────┘
         [ 记一笔支出 ]   ← 唯一按钮
```

- **收入那行自动来**（`transactions.pay_method` 汇总），不让他录，避免了和微信正面竞争
- **只有"支出"要他动手**，一个月十几次
- 底下那句"本月到手 5,180"是微信永远给不了的数 —— 这是唯一的护城河

## 7.4 卖给他的一句话（换掉上一版所有话术）

> 「微信告诉你今天收了多少。但你上个月收了 3 万，进货掏出去 2 万 2、房租 3 千、工钱 2 千、
> 报损 1 千 —— **真正落进口袋的是 5 千，这 5 千微信一行都看不见。**」

不再提毛利率、不再提"数字化管理"。

## 7.5 唯一需要验证的事（半天，比改三天便宜）

**不问"你愿不愿意用"，问"上个月你掏出去了多少"。**

随便挑一个月，让他自己报：进货 / 房租 / 工钱 / 水电 / 报损 各多少，加起来多少。
- **报不出来或报得含糊** → 第 ① 条痛点成立，做 7.3 那块板。
- **张口就来、一分不差** → 他心里有本明账，**他真不是我们的客户**，别改代码。
